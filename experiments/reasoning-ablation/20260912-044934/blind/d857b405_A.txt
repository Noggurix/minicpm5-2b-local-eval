

To illustrate the use of `QuantumCache` we first import it and then create a small async routine.  The routine stores a value under a simple key, attaches a 30‑second time‑to‑live (TTL) on the set operation, and then fetches it with `await cache.get(...)`.  The code also shows how to wait a little longer than the TTL and then see that the entry has been evicted.

```python
import asyncio
import time
from quantumcache import QuantumCache

async def main():
    # ------------------------------------------------------------------
    # Create a QuantumCache instance.  By default the instance is local
    # (see the note below) – you can request a shared instance with
    # QuantumCache.shared() if you need cross‑process access.
    # ------------------------------------------------------------------
    cache = QuantumCache()

    key = "my_key"
    value = {"msg": "Hello from QuantumCache"}

    # ---------------------------------------------------------------
    # Store a value with a 30‑second TTL.
    # ---------------------------------------------------------------
    # The exact method name depends on the implementation; the common
    # pattern is cache.set(key, value, ttl=30).  In the event that the
    # module uses a different signature you would adapt it accordingly.
    await cache.set(key, value, ttl=30)

    # ---------------------------------------------------------------
    # Retrieve the value asynchronously.
    # ---------------------------------------------------------------
    retrieved = await cache.get(key)
    print("Immediately after set:", retrieved)

    # ---------------------------------------------------------------
    # Let the cache expire (a little longer than the TTL).
    # ---------------------------------------------------------------
    await asyncio.sleep(35)

    # After the expiry the entry should be gone.
    try:
        expired = await cache.get(key)
        print("After expiry:", expired)
    except KeyError:
        print("Entry expired (KeyError raised).")

if __name__ == "__main__":
    asyncio.run(main())
```

**Why the `await` is needed**

`QuantumCache.set` and `QuantumCache.get` are declared async in the library, so you have to `await` them.  Without the `async/await` construct you would be blocking the event loop and would have to run these calls in a normal thread.

## `QuantumCache.local()` vs. `QuantumCache.shared()`

| Feature | `QuantumCache.local()` | `QuantumCache.shared()` |
|---------|-----------------------|------------------------|
| **Scope** | Created **per‑thread/process** for the current execution context (e.g., a single Python process or a single thread).  It cannot be used in another process without an explicit bridge. | Created **once per host** and can be accessed from **any thread or process** that imports the module (or that you explicitly share). |
| **Use‑case** | When you only need caching inside a single script, a single request‑processing loop, or a library module that expects the cache to be bound to the current thread. | When you want a **central cache** that can be shared across multiple threads, processes, or even different Python runs (e.g., in a distributed system). |
| **Implementation note** | In the default `QuantumCache()` constructor you get a *local* instance.  If you want a *shared* instance you must call `QuantumCache.shared()` (or import a pre‑created shared instance). | `QuantumCache.shared()` returns the **same** shared cache every time it is called, so you can guarantee that two places in your program are using the same backing store. |
| **Performance impact** | A small overhead of creating a new wrapper for each thread/process, but otherwise the cache is dedicated to that context. | A tiny overhead for the first creation (if the cache is not yet mounted) but thereafter the shared cache benefits from common invalidation and batch‑dictionary handling. |
| **Typical pattern** | ```python cache = QuantumCache()``` (default) | ```python cache = QuantumCache.shared()``` |

**Bottom line**  
- `QuantumCache.local()` is the “default” instance, meant for single‑process, single‑thread usage.  
- `QuantumCache.shared()` is a wrapper that guarantees the *same* cache is used across different threads, processes, or even different Python sessions, which is useful when you need cross‑process caching or when multiple parts of a larger program should share the same time‑to‑live entries.  

If you only need caching inside the script that runs the `async` loop, the simple `QuantumCache()` you used above is enough.  When you expect concurrency across processes or need a shared cache for distributed use, switch to `QuantumCache.shared()`.
